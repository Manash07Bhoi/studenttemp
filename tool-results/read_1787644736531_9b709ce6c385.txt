     1→# StudentTemp — Project Worklog
     2→
     3→## Project Overview
     4→**StudentTemp** is a privacy-first temporary email platform built for students, developers, and testers.
     5→Adapted from a detailed PRD to our Next.js 16 + Prisma + Socket.IO stack. The PRD specified
     6→Vite/React/Go/Postgres, but we delivered an equivalent feature set on Next.js with SQLite + a
     7→socket.io mini-service that simulates real SMTP receipt by generating realistic incoming mail
     8→(OTP codes, registration confirmations, newsletters, social notifications, security alerts, etc.).

   104→## Unresolved issues or risks, and priority recommendations for the next phase
   105→
   106→### Known limitations (by design)
   107→1. **Mock email generation, not real SMTP** — the PRD specified real Postfix SMTP receipt, which
   108→   is impossible in this sandbox. The mail-service generates realistic synthetic mail instead.
   109→   This is clearly disclosed in the About section FAQ.
   110→2. **Session stored in a non-HttpOnly cookie fallback** — the session ID is created server-side
   111→   and set via `Set-Cookie` header, but since this is a demo without auth middleware, the cookie
   112→   is set on the API response. The getSessionOrCreate helper handles both new and existing sessions.
   113→
   114→### Recommended next-phase work
   115→1. **Swipe gestures on message cards** — the PRD's MOTION-SYSTEM.md specifies swipe-left-to-delete
   116→   and swipe-right-to-toggle-read. Currently only hover/click quick-actions are implemented.
   117→   Priority: Medium (nice-to-have polish).
   118→2. **Sound feedback** — the settings toggle exists but no actual sound is played on new mail.
   119→   Need a short WebAudio chime. Priority: Low.
   120→3. **Pull-to-refresh on mobile** — specified in motion system, not yet implemented. Priority: Low.
   121→4. **Multi-tab sync (BroadcastChannel)** — read/unread state could desync across tabs of same
   122→   origin. Priority: Medium.
   123→5. **Image generation for About/empty states** — could use the image-generation skill to create
   124→   branded illustrations for the empty states and About hero. Priority: Low.
   125→6. **More email template variety** — currently 7 templates; could add more Indian-context templates
   126→   (UPI payment confirmations, exam hall tickets, etc.). Priority: Low.
   127→7. **Admin panel** — the AbuseReport model exists but there's no admin view to review reported
   128→   messages. Priority: Low (was Phase 3 in PRD).
   129→8. **Search across all inboxes** — current search is per-inbox. Could add global search.
   130→   Priority: Low.
   131→
   132→### Risk: gateway port assumption
   133→The socket connection relies on the Caddy gateway (`?XTransformPort=3003`). When testing with
   134→`agent-browser open http://localhost:3000` (direct, bypassing gateway), the socket fails silently.
   135→Always test via `http://localhost:81` (the gateway). The Preview Panel uses the gateway, so end
   136→users are unaffected.
